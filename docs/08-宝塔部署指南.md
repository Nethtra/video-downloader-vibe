# 宝塔面板部署指南（从零到上线）

> 适用：把「极易下」部署到中国大陆云服务器 + 宝塔面板。
> 写作时间：2026-10-12；2026-10-23 校对并补充「当前线上实例」与实测结论。
> 宝塔面板版本以 13.x 为准，系统推荐 Ubuntu 22.04 / Debian 12；本项目线上实际使用 Alibaba Cloud Linux 3（RHEL 系，命令用 `yum/dnf`）。
>
> **本项目的部署优势**：单服务架构——前端已编译进 `backend/static`，由 FastAPI 一起托管，
> 服务器上只需要跑**一个 Python 进程**（端口 8000），不用装 MySQL、不用装 PHP、不用 Node 构建。

## 0. 当前线上实例（2026-10-23 实况）

| 项 | 实际值 |
|---|---|
| 服务器 | 阿里云轻量应用服务器 · 中国香港 · 2C2G |
| 系统 | Alibaba Cloud Linux 3（RHEL 8 系） |
| 面板 | 宝塔 13.x（Python 项目守护 + Nginx 反代） |
| Python | 宝塔虚拟环境 3.12（`/www/server/pyporject_evn/...`，注意面板就是这么拼的） |
| Node | v24.21（YouTube 签名求解 + yt-dlp PO Token 插件依赖） |
| yt-dlp | 2026.8.19（发布当时 GitHub Latest） |
| 域名 / 证书 | 自有域名（下文用 `https://你的域名` 代指）· Let's Encrypt · 强制 HTTPS |
| 进程形态 | 单进程 uvicorn，端口 8000，Nginx 反代 |

**上线后实测（重要，不要重复踩坑）**：

| 平台 | 结果 | 结论 |
|---|---|---|
| 抖音 | ✅ 下载正常 | 自研通道不依赖 IP 信誉 |
| B站 下载 | ❌ `HTTP 412` | 香港 DC IP 对未签名内容请求风控；签名 playurl 与 CDN 实测可通过，方案见 docs/09（搁置） |
| B站 AI 总结 | ✅ 正常 | 走独立 `dm/view` 字幕通道，不经 yt-dlp |
| YouTube | ❌ `Sign in to confirm you're not a bot` | 数据中心 IP 登录墙；node、yt-dlp 最新版、PO Token（bgutil）均已排除，属 IP 层限制 |

> 结论：**同一份代码在家宽 IP 上 B站/YouTube 均正常**，服务器上的失败是 IP 信誉问题，不是代码或版本问题。
> 详细排查记录见本文「YouTube IP 风控实战结论」。

## 部署全景图（先建立认知，再动手）

```
买服务器 → 装宝塔面板 → 装基础环境(ffmpeg/Python) → 上传项目代码
   → 创建 Python 项目(跑在 8000) → IP 直连测试
   → 买域名 → ICP 备案(1~3周) → 域名解析 → Nginx 反向代理 + HTTPS → 正式上线
```

备案周期长，所以**第 6 步之前不需要等任何人**：服务器一就位就能用 `IP:8000` 把网站跑起来，
备案和后续步骤可以并行推进。

## 第 1 步：购买云服务器

| 项 | 推荐 | 说明 |
|----|------|------|
| 厂商 | 腾讯云 / 阿里云 | 都有新用户优惠的轻量应用服务器 |
| 类型 | **轻量应用服务器**（Lighthouse / SWAS） | 比 CVM/ECS 便宜、自带防火墙面板，新手友好 |
| 配置 | **2核2G 起** | 本项目很轻（SQLite + 单进程），2G 足够 |
| 地域 | 中国大陆任意（就近选） | 你已确认大陆。注意代价：域名必须备案、YouTube 不可用 |
| 系统 | **Ubuntu 22.04 LTS**（或 Debian 12） | 宝塔官方推荐，安装命令完全一致 |
| 流量 | 轻量机自带月流量包（如 1TB） | ⚠️ 见下方流量说明 |

**⚠️ 流量成本提醒（这个商业模式必须心里有数）**：
用户下载视频 = 服务器从 B站/抖音下载 → 中转给用户，**出站流量 ≈ 视频大小**。
一个 200MB 的视频就消耗 200MB 月流量包。个人站初期流量包够用，但要留意用量，
超套餐后按量计费。以后用户量大了，带宽会是主要成本项。

## 第 2 步：安装宝塔面板

1. **登录服务器**：云控制台提供网页版 SSH 终端（腾讯云叫 OrcaTerm，阿里云叫 Workbench），
   点「登录」输入 root 密码即可，不用装 Xshell。
2. **拿安装命令**：打开宝塔官网 https://www.bt.cn/new/download.html ，
   复制「通用安装脚本」（选 Ubuntu/Debian 那条）。命令带账号个性化参数，**不要抄别人的**。
3. 在服务器终端粘贴执行，约 2 分钟装完。**结束时屏幕会打印**：
   - 面板访问地址（形如 `http://服务器IP:随机端口/安全入口字符串`）
   - 用户名和密码 → **截图保存，这是面板的钥匙**
4. **放行面板端口**：在云控制台的「防火墙/安全组」里，放行面板端口（打印信息里有，随机如 `38xxx`）。
   浏览器打开面板地址，输入账号密码登录，绑定你注册的宝塔账号。

> 忘记账号密码：服务器终端执行 `bt default` 可重新查看；`bt 5` 可重置密码。

## 第 3 步：宝塔里装基础环境

**3.1 跳过 LNMP 全家桶**：首次进面板会弹「推荐安装套件」（Nginx/MySQL/PHP）。
MySQL、PHP **本项目用不到**（我们用 SQLite），可以先不装或只勾 Nginx（第 7 步反代要用）。
以后随时能在「软件商店」补装。

**3.2 安装 Python 版本**：新版宝塔在 **网站 → Python项目 → 版本管理** 里在线安装 Python
3.12（或 3.10+，任选一个较新稳定版）。项目对版本无硬性要求，别用 3.8 以下即可。

**3.3 安装 ffmpeg（必装！）**：B站/YouTube 等平台的高清视频是音画分离的（DASH），
下载时需要 ffmpeg 合并音轨，**没有它高清只能拿到无声视频**（代码会自动退化为低清渐进式）。
SSH 终端一条命令：

```bash
apt update && apt install -y ffmpeg
ffmpeg -version   # 验证装好了
```

**3.4 Node.js（海外/香港必装，大陆可不装）**：YouTube 解析依赖 node 做签名求解（nsig），
自研的 bgutil PO Token 插件也依赖 node。大陆服务器直连不了 YouTube 可以先不装；
香港/海外节点**必须装 node 22+**（本项目线上为 v24），否则 YouTube 会误报 bot check / 年龄墙。
Alibaba Cloud Linux / RHEL 系用 NodeSource 源：

```bash
curl -fsSL https://rpm.nodesource.com/setup_22.x | sudo bash -
sudo yum install -y nodejs
node -v   # 输出 v22.x 或更高
```

## 第 4 步：本地打包上传项目

### 4.1 本地先做两件事

```bash
# ① 确保前端构建产物是最新（产物在 backend/static，这是网站页面的来源）
cd D:\code\video-downloader\frontend
npm run build

# ② 编辑 backend/.env，预填线上配置（SITE_URL 先写占位，备案后改成真域名）
```

### 4.2 打包内容（Windows 右键压缩即可）

把 `D:\code\video-downloader` 压缩成 zip，**排除这些目录**：

| 排除 | 原因 |
|------|------|
| `frontend/node_modules/` | 几百 MB，服务器不需要 |
| `frontend/node_modules 以外的 frontend 源码` | 可留可不留，服务器上用不到 |
| `backend/downloads/` | 本地测试残留 |
| `backend/.test-downloads/`、`.workbuddy/`、`.tools/` | 工作区私有数据 |
| `backend/data/app.db` | 可选：**不带** = 线上从全新库开始（推荐，干净）；带上 = 延续本地测试账号 |

**必须包含**：`backend/`（含 `app/`、`static/`、`requirements.txt`、`.env`、`run.py`）、`docs/`、`README.md`。
`.env` 里有 API key，只传到**你自己的服务器**没问题；但注意别把这个 zip 分享给别人。

### 4.3 上传解压

宝塔面板 → 文件 → 进入 `/www/wwwroot/` → 上传 zip → 右键解压，
最终保证这个路径存在：

```
/www/wwwroot/video-downloader/backend/run.py
```

（zip 里若多套了一层目录，把内层移动出来对齐上面的路径即可。）

## 第 5 步：创建 Python 项目（核心步骤）

宝塔面板 → **网站 → Python项目 → 添加Python项目**，逐项填写：

| 表单项 | 填什么 | 说明 |
|--------|--------|------|
| 项目名称 | `yijixia` | **必须英文**，面板按它建虚拟环境 |
| 项目路径 | `/www/wwwroot/video-downloader/backend` | run.py 所在目录 |
| Python版本 | 选你装好的 3.12 | |
| 启动方式 | **命令行启动** | FastAPI 项目选这个 |
| 启动命令 | `python run.py` | run.py 内部就是 uvicorn，读 `PORT` 环境变量、默认 8000 |
| 端口 | `8000` | |
| 安装依赖 | 勾选/指向 `requirements.txt` | 4 个包：fastapi、uvicorn、yt-dlp、stripe |
| 开机自启 | ✅ 勾选 | 面板会做进程守护，崩了自动拉起 |

> **⚠️ 千万不要用多 worker 启动**（如 `uvicorn --workers 4` 或 gunicorn 多进程）。
> 本项目的下载任务表、总结任务、SSE 推送都存在**进程内存**里，多 worker 会把状态打散，
> 出现「提交了任务却查不到进度」的灵异 bug。单进程就是设计好的正确形态。

启动后看项目管理器的「项目日志」，出现 `Uvicorn running on http://0.0.0.0:8000` 即成功。

## 第 6 步：IP 直连测试（不用等备案）

1. 云控制台防火墙放行 **8000 端口**（TCP）。
2. 浏览器打开 `http://服务器IP:8000` → 应看到完整网站。
3. 依次验证：
   - **下载**：粘一个 B站链接，选 1080p 下载，能下载且**有声音**（验证 ffmpeg 生效）
   - **AI 总结**：粘一个带字幕的 B站视频，总结流式输出正常
   - **注册登录**：注册一个账号（此时库是全新的，是线上第一个用户）

> 若 502 或打不开：看 Python 项目的「项目日志」。九成是依赖没装全（缺 stripe 最常见）
> 或端口没放行。

## 第 7 步：域名 + 备案 + 反向代理 + HTTPS

### 7.1 备案（大陆服务器绕不开，先启动）

大陆服务器要对外开 80/443 网页服务，域名**必须 ICP 备案**（个人备案免费，1~3 周）。
流程：在云厂商备案平台提交（腾讯云 beian.cloud.tencent.com / 阿里云 beian.aliyun.com）
→ 实名认证 + 填网站信息（个人学习用途、博客类目即可，别写"视频下载"字样，写「个人技术博客/工具站」更顺利）→ 管局审核。
**备案期间服务器和 8000 端口不受影响**，正常开发测试。

### 7.2 域名解析

备案通过后，域名 DNS 添加 A 记录：`@` 和 `www` 都指向服务器公网 IP。

### 7.3 宝塔建站 + 反向代理

1. 网站 → 添加站点：域名填你的域名，纯静态即可（不要 PHP）。
2. 站点设置 → **反向代理 → 添加反向代理**：目标 URL `http://127.0.0.1:8000`。
3. **⚠️ 反代配置必须改两处（本站特有的坑，别的教程不会告诉你）**：

打开反代的配置文件，在 `location /` 段里**追加**：

```nginx
# ① AI 总结用 SSE 流式输出，Nginx 默认会攒缓冲，导致前端"转圈很久突然全出"
proxy_buffering off;

# ② 长视频 AI 总结（map-reduce）最长可跑 15 分钟，Nginx 默认 60 秒就断流
proxy_read_timeout 1200s;
proxy_send_timeout 1200s;
```

保存并重载 Nginx。没配 ①，AI 总结的逐字输出会变成卡顿后一次性弹出；
没配 ②，长视频总结到一半会报 504/连接中断。

### 7.4 HTTPS 证书

站点设置 → **SSL → Let's Encrypt** → 勾域名申请（免费）→ 开启「强制 HTTPS」。
宝塔自动续期，不用管。

### 7.5 上线收尾

- `backend/.env` 里把 `SITE_URL=https://你的域名` 填上 → 项目管理器里**重启项目**
  （SEO 的 canonical/sitemap/llms.txt/OG 链接全部自动跟随这个值）
- 浏览器访问 `https://你的域名`，重复第 6 步三项验证
- Stripe 正式收款要等用 Live 密钥后，在 Dashboard 配公网 webhook 地址
  `https://你的域名/api/pay/stripe/webhook`（详见 docs/06）

## 常见问题速查

| 现象 | 大概率原因 |
|------|-----------|
| 502 Bad Gateway | Python 项目没跑起来 → 看项目日志；缺依赖（ModuleNotFoundError: stripe 最常见） |
| 页面能开，接口全 504 | 反代没加 `proxy_read_timeout`，或 8000 端口没放行 |
| AI 总结转圈很久才一次性出结果 | 反代没加 `proxy_buffering off` |
| 高清视频没声音 / 只有 720p | 服务器没装 ffmpeg |
| 某平台突然全部解析失败 | yt-dlp 版本旧了，先升级再排查 |
| 域名访问被重置/打不开，IP:8000 正常 | 备案没下来或没通过（大陆服务器 80/443 强制拦截未备案域名） |

## 变体：部署到中国大陆之外（让用户能解析 YouTube）

> 推荐地域：**中国香港**。离大陆最近（延迟约 30~50ms，用户几乎无感）、免备案、
> YouTube 可用。腾讯云/阿里云轻量服务器都有香港节点，买法与大陆完全相同。
> 新加坡/日本/美国也可，但离大陆越远国内用户访问越慢。

### 与大陆部署的差异对照

| 事项 | 中国大陆 | 中国香港（海外） |
|------|:---:|:---:|
| ICP 备案 | 必须（1~3 周） | **不需要**，域名解析当天可用 |
| YouTube 解析 | ❌ 不可用 | ✅ **可用**（必须加装 node，见下） |
| B站下载解析 | 稳定 | ❌ 香港 DC IP 实测 412（未签名内容请求被拦）；**AI 总结走 dm/view 通道不受影响**；绕行方案见 docs/09 |
| 抖音 | 稳定 | 未实测，海外 IP 访问抖音接口存在不确定性 |
| 国内用户速度 | 最快 | 香港接近无感，其余地区明显变慢 |
| 价格 | 便宜 | 略贵 |

> 没有一个机房位置能同时完美满足「B站/抖音要大陆 IP」和「YouTube 要海外网络」，
> 香港是最实用的折中。若必须两全，见文末「鱼与熊掌方案」。

### 流程调整（其余步骤与主教程完全相同）

1. **第 1 步**买服务器时地域选「中国香港」，配置/系统选择不变。
2. **第 3 步必须加装 Node.js 22**（YouTube 解析的签名求解依赖 node，大陆部署可省略；
   注意别用 `apt install nodejs`——Ubuntu 仓库里的版本太旧会导致签名失败）：

   ```bash
   curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
   sudo apt-get install -y nodejs
   node -v   # 输出 v22.x 才算成功
   ```

3. **第 7 步跳过备案**：域名购买后直接 DNS 解析到服务器 IP → 建站点 → 反向代理 →
   SSL 证书，当天可完成 HTTPS 上线。
4. 第 4~6 步、反代的两条 SSE 配置、SITE_URL 收尾——**一字不差照旧**。

### YouTube IP 风控实战结论（2026-10-20 实测：阿里云香港轻量）

香港数据中心 IP 部署后实测：**B站下载解析 412、YouTube "Sign in to confirm you're not a bot"，而同一份代码在本地家宽 IP 上完全正常**——纯 IP 信誉问题。已穷尽无 cookie 路线：

| 手段 | 结果 | 说明 |
|---|---|---|
| node v24 就位 | ✅ 排除 | 签名求解正常，排除"node 缺失"假说 |
| yt-dlp 2026.8.19（当时最新） | ✅ 排除 | 本地同版本正常，排除版本假说 |
| player_client 轮换（android_vr / tv_downgraded / mweb / web_embedded） | ❌ 全灭 | 免 PO Token 的客户端全部被拦 |
| **bgutil-ytdlp-pot-provider**（PO Token 自动生成，脚本模式） | ⚠️ 部署成功，被更深层拦截 | BotGuard 流程已触发（Detected experiment to bind GVS PO Token），但 YouTube 直接给 IP 登录墙 |

**YouTube 的封锁是分层的**（官方 issue #37）：第一层 bot check（PO Token 可解）→ 第二层 **IP 登录墙（只有 Cookie 或住宅代理能过）**。数据中心 IP 被打到第二层是常态，PO Token 不是银弹。

#### 已部署并保留的基础设施（将来换 IP / 加代理后立即生效）

- yt-dlp 插件（zip 直装）：`/etc/yt-dlp/plugins/bgutil-ytdlp-pot-provider.zip`
  > 注意：pip 的命名空间包方式（`pip install bgutil-ytdlp-pot-provider`）在宝塔 Python（`/www/server/pyporject_evn`，非标准 venv 布局）下**不被 yt-dlp 发现**，必须用 release zip 放系统级插件目录
- POT 生成脚本（脚本模式，无常驻服务）：`/root/bgutil-ytdlp-pot-provider/server`（`npm ci && npx tsc` 已编译）
- 加载验证：`yt-dlp -v URL 2>&1 | grep -i "PO Token Providers"` —— 看到 `bgutil:script-node-2.0.2 (external)` **不带 unavailable** 即加载成功
- 原理：yt-dlp 解析时自动 spawn node 执行 BotGuard 挑战脚本生成通行令牌（每次约 1 秒），全程无 cookie、无常驻进程

#### 将来 YouTube 恢复的三条路径（按推荐排序）

1. **换未标记的 IP**（换实例/换服务商）——bgutil 已就位，若新 IP 只被第一层拦截，PO Token 直接生效，零额外操作
2. **住宅代理**（付费）——写入 `backend/proxy.txt` 即可
3. **Cookie**（免费，需定期维护）——`backend/cookies/cookies.txt`

#### B站 412 同理

B站无插件级方案（yt-dlp 生态没有 PO Token 等价物），社区解法只有 cookie/代理。无 cookie 根治路线 = **自研 playurl 通道**（WBI 签名 + dm 指纹参数 + try_look），完整设计、接口参数与实测结论见 **`docs/09-B站直连通道方案.md`**。

2026-10-20 已在该服务器上完成全链路验证：签名 `playurl` 返回 1080P、CDN 直链 206（视频/音频），**不需要换 IP**；
2026-10-23 决定暂缓实施（优先级与长期维护成本），代码未开工。当前 B站 **AI 总结不受影响**（独立 dm/view 通道）。

### 鱼与熊掌方案：大陆服务器 + 代理出口（了解即可）

本项目代理解析顺序为 `backend/proxy.txt` > 系统 ProxyHandler，因此在大陆服务器上
自建代理客户端并把地址（如 `http://127.0.0.1:7890`）写入 `backend/proxy.txt`，
即可实现 B站/抖音直连、YouTube 走代理出海外。技术上两全，但代理的搭建/购买、
稳定性与合规性需自行评估，个人项目不作首选推荐。
