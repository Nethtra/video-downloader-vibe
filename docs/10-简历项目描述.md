## 版本 A：完整版（项目经历栏空间充足）

**极易下 — 万能视频下载与 AI 内容总结平台**（个人全栈项目 · 已部署上线）

技术栈：Vue 3 + Vite / FastAPI + yt-dlp / SQLite / Stripe / DeepSeek（OpenAI 兼容）/ SSE

- 独立完成「视频解析下载 + AI 总结」一体化 Web 平台：前端 Vue 3 单页应用、后端 FastAPI 单进程，构建产物由后端托管，宝塔 + Nginx + HTTPS 部署在自有云服务器。
- 设计多通道解析架构：抖音走自研免 Cookie 通道（服务端铸造访客 `ttwid` + 移动分享页，无水印、支持口令/短链）；B站字幕走独立 `dm/view` 弹幕池通道（BV→aid 纯算法转换，免登录免签名）；其余平台统一交给 yt-dlp，失败按平台回退。
- 实现基于 SSE 的流式 LLM 管道：后台线程调用模型并增量写入缓冲，前端 EventSource 实时渲染；断线/刷新不丢结果，轮询兜底；长视频自动切换 map-reduce 分块摘要（262 分钟视频全片覆盖，章节时间取自字幕真实时间戳）。
- 设计 LLM 输出解析与容错体系：markdown 分节 + 思维导图围栏解析、格式变体兼容、解析阈值宽于 prompt 上限、真实 bad case 离线回归；字幕语言排序（中文 > 原语言 > 英文 > 任意）。
- 实现完整支付与会员系统：SQLite 四表（用户/会话/订单/webhook 去重）、scrypt 密码哈希 + HttpOnly Cookie、Stripe Checkout、三层幂等（幂等键/事件去重/订单原子状态机）、服务端强制权益门禁（非会员 1080p 上限、AI 每日限额）。
- 落地 SEO/GEO：后端运行时注入 canonical/OG/JSON-LD（WebSite/Organization/WebApplication/HowTo/FAQPage）与可引用静态正文，输出 `robots.txt`、`sitemap.xml`、`llms.txt`；站点支持 6 语言（零依赖 i18n）与三态深色模式。
- 完成整站品牌与体验重构：瑞士国际主义设计系统（12 栏网格、纸白/墨黑/强调红、零圆角阴影）、自托管 Instrument Serif + Inter（latin 子集 91KB）、基于 IntersectionObserver 的滚动入场与首屏分级动效，并适配移动端 360px 宽度。

## 面试追问准备（不写进简历）

1. **B站字幕为什么不用 `player/wbi/v2`？**
   该接口需要登录态，未登录对热门长视频稳定返回空字幕列表；`x/v2/dm/view` 是弹幕池元信息接口，不校验登录，
   返回的 `subtitle.subtitles` 含原生中文与多语 AI 轨，直链 `aisubtitle.hdslb.com` 无需鉴权。
2. **服务器上 B站为什么 412？后来怎么定位的？**
   实测 412 只落在**未签名内容请求**（视频页 HTML、未签名 `view`）；`spi/nav/签名 view-wbi/签名 playurl` 全 200，
   CDN 也能 206 拉流。结论：yt-dlp 第一步抓视频页就被打断，不是取流被封。自研签名通道已验证可行（docs/09），
   但评估维护成本后搁置。
3. **YouTube 在服务器上为什么不行？**
   分两层：bot check（PO Token 可解）与 IP 登录墙（只有 Cookie/住宅代理能过）。已实测 node、最新 yt-dlp、
   player_client 轮换、bgutil PO Token 全部排除，属数据中心 IP 限制。
4. **为什么任务存内存而不是 Redis？**
   任务生命周期只有 30 分钟、单机单进程部署，内存字典 + TTL 足够；引入 Redis 会增加部署与运维成本。
   代价是重启丢失进行中任务、不能多 worker——已在文档中明确约束。
5. **SSE 断线怎么办？**
   LLM 在后台线程执行，增量写入 `stream_buf`；SSE 只负责搬运。前端断开/刷新后可用轮询接口取回最终结果，
   不会重复消耗模型调用。
6. **支付幂等怎么做？**
   ① 创建 Session 带 `idempotency_key`；② webhook 事件按 `event.id` 去重；③ 订单 `UPDATE ... WHERE status!='paid'`
   原子流转，只有 rowcount=1 才叠加会员时长；webhook 丢失时前端回跳轮询主动向 Stripe 查询兜底。
7. **怎么保证 LLM 输出可解析？**
   prompt 约束 + 解析端多种格式变体兼容 + 截断阈值宽于 prompt 上限 + 真实 raw 样本离线回归；
   章节时间必须来自素材中带时间戳的行，否则模型会按比例估算。
