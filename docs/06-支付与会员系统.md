# 06 - 支付与会员系统（Stripe + 登录体系）

> 2026-10-10 实现。前置文档：01 需求分析 / 02 方案设计 / 03 AI 视频总结 / 04 功能扩展 / 05 SEO。
> 本文是支付与会员模块的架构说明 + 站长运维手册（Stripe 配置、测试、上线切换）。

## 1. 功能总览

| 能力 | 说明 |
|---|---|
| 登录系统 | 邮箱+密码注册/登录（无邮箱验证），HttpOnly Cookie 会话（30 天），SQLite 持久化 |
| Stripe 支付 | Checkout Session 托管支付页（mode=payment 一次性购买），收款币种 CNY |
| 会员开通 | 月卡 +30 天 / 年卡 +365 天，从现有到期时间**叠加**；订单归属登录用户 |
| 幂等保障 | 三层防重：idempotency_key（Stripe 侧）/ webhook 事件去重表 / 订单原子状态机 |
| 会员权益（真实可兑现） | AI 视频总结不限次；下载清晰度解除 1080p 上限（服务端强制） |
| 多语言价格 | 收款始终 CNY；非中文界面显示静态汇率换算参考价（≈ 符号） |
| Mock 回退 | 未配置 `STRIPE_API_KEY` 时自动回退模拟收银台，本地无密钥可全流程联调 |

## 2. 架构与文件

**新增**
- `backend/app/db.py`：SQLite 封装（`backend/data/app.db`，WAL）。四张表：`users`（email/scrypt 密码哈希/vip_until）、`sessions`（token/user_id/expires_at）、`orders`（order_id/user_id/plan_id/amount_cents/status/stripe_session_id）、`processed_webhook_events`（event_id 去重）
- `backend/app/auth.py`：注册/登录（scrypt n=2^14 加盐 + 常量时间比较）、会话 cookie（`sid`，HttpOnly + SameSite=Lax，`COOKIE_SECURE=1` 时加 Secure）、`current_user()` / `is_vip()`
- `backend/app/envutil.py`：统一 .env 加载（与 summarizer 原有逻辑幂等共存）
- `frontend/src/currency.js`：静态汇率换算参考价

**修改**
- `backend/app/payments.py`：`StripeProvider`（Checkout Session 创建/查询/webhook 验签）+ `fulfill_order()` 统一履约（mock confirm 与 webhook 共用）+ PLANS 增加 `days` 字段
- `backend/app/main.py`：`/api/auth/*` 4 条路由、`/api/pay/stripe/webhook`（原始 body 验签）、下单需登录、CORS 收紧为 `ALLOWED_ORIGINS` 白名单（默认仅同源）、清理任务追加过期会话清理
- `backend/app/summarizer.py`：`start_summary(..., exempt=)`、`quota_of(..., vip=)` —— 会员跳过 IP 每日限流
- `backend/app/downloader.py`：`start_download(..., max_height=)` —— 非会员 fmt 整体替换为 `bv*[height<=1080]+ba/b[height<=1080]/b`（不信任前端 format_id）；音频提取与抖音通道不受影响
- `frontend/src/App.vue`：登录/注册弹窗、导航栏用户区（邮箱前缀 + VIP 徽章 + 有效期）、startPay 跳 Stripe、`?pay=success&order=` 回跳确认、4K chip 会员锁、价格参考价

**API 一览**

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | `{email,password}` → Set-Cookie；409 已注册 / 400 弱密码 |
| POST | `/api/auth/login` | 401 凭证错误 |
| POST | `/api/auth/logout` | 删会话 + 清 cookie |
| GET | `/api/auth/me` | `{user: {email, vip_until, is_vip} \| null}`，恒 200 |
| GET | `/api/pay/config` | `{provider: "stripe" \| "mock"}` |
| POST | `/api/pay/order` | **需登录**。`{plan_id, locale}` → `{order_id, pay:{pay_type, pay_url, session_id}}` |
| POST | `/api/pay/stripe/webhook` | Stripe 回调（原始 body + Stripe-Signature）；验签失败 400 |
| POST | `/api/pay/mock/confirm` | **仅 mock 渠道可用（生产 403）**，走统一履约 |
| GET | `/api/pay/order/{id}` | paying 时主动向 Stripe 同步一次（webhook 未达兜底） |

## 3. 支付流程

```
未登录点购买 ──> 登录/注册弹窗 ──> 登录成功自动继续购买
已登录 ──> POST /api/pay/order ──> 返回 Stripe Checkout URL ──> 跳转托管支付页
  ├── 支付成功：Stripe 发 webhook（checkout.session.completed）→ 验签 → 事件去重 → 原子置 paid → vip_until 叠加
  │            同时浏览器回跳 ?pay=success&order=xxx → 前端弹「确认中」轮询 → paid → 显示会员有效期
  └── 取消：回跳 /#pricing，订单停留 paying
```

- **幂等三层**：① Session 创建带 `idempotency_key=order_{order_id}`；② `processed_webhook_events` 按 event.id 去重（Stripe 会重发）；③ `UPDATE orders SET status='paid' WHERE status!='paid'` 原子迁移，rowcount=1 才 `extend_vip`
- **不丢单**：webhook 未达时，前端回跳轮询触发 `query_order` → 后端主动 `Session.retrieve` 同步
- **安全**：webhook 强制验签（`construct_event`，300s 容差）+ 原始 body；履约只认 `metadata.order_id` 查本地订单；order_id 随机不可猜；密码 scrypt；退款/争议事件本期仅入库留痕不自动撤销会员

## 4. 站长配置手册（Stripe）

### 4.1 获取测试密钥（Test Mode）
1. 登录 [dashboard.stripe.com](https://dashboard.stripe.com)，右上角打开 **Test mode**
2. Developers → API keys → 复制 **Secret key**（`sk_test_...`）
3. 写入 `backend/.env`：`STRIPE_API_KEY=sk_test_...`

### 4.2 本地 webhook（开发/测试必做）
1. 安装 Stripe CLI：GitHub Releases 下载 `stripe_X.X.X_windows_x86_64.zip` 解压，或 `scoop install stripe`
2. `stripe login`（浏览器授权）
3. 新窗口执行：`stripe listen --forward-to localhost:8000/api/pay/stripe/webhook`
4. 把终端输出的 `whsec_...` 写入 `.env`：`STRIPE_WEBHOOK_SECRET=whsec_...`（**每次 listen 会更换，注意同步**）
5. 重启后端。可用 `stripe trigger checkout.session.completed` 验证链路

### 4.3 测试卡（Test Mode）
| 卡号 | 场景 |
|---|---|
| `4242 4242 4242 4242` | 支付成功 |
| `4000 0000 0000 9995` | 拒绝（订单停留 paying） |
| `4000 0025 0000 3155` | 3DS 验证流程 |

有效期填任意未来日期，CVC 任意 3 位。

### 4.4 验收要点
1. 支付完成后：后端日志出现 webhook 事件且无重复处理；订单 paid；`/api/auth/me` 的 `vip_until` 正确
2. 幂等：`stripe trigger checkout.session.completed` 重放同一事件，会员有效期**不再延长**
3. 兜底：关掉 `stripe listen` 再走一遍支付（模拟 webhook 丢失），回跳页轮询数秒内仍变 paid

### 4.5 上线切换（Live Mode）
1. Dashboard 切回 Live mode，取 `sk_live_...`；确认账户已启用 **CNY 收款**（香港主体支持；Test Mode 无此限制）
2. Dashboard → Developers → Webhooks → **Add endpoint**：URL 填 `https://你的域名/api/pay/stripe/webhook`，事件勾选 `checkout.session.completed`、`checkout.session.async_payment_succeeded`、`checkout.session.async_payment_failed`；把 endpoint 签名密钥 `whsec_...` 配到线上环境
3. `.env`：`SITE_BASE_URL=https://你的域名`、`COOKIE_SECURE=1`
4. 部署上传 backend 目录时 `.env` 一并带上（含密钥，勿提交 git）

## 5. 环境变量（backend/.env）

| 变量 | 说明 |
|---|---|
| `STRIPE_API_KEY` | 空 = Mock 模拟支付；填 `sk_test_/sk_live_` = 真实 Stripe |
| `STRIPE_WEBHOOK_SECRET` | webhook 验签密钥（`whsec_`） |
| `SITE_BASE_URL` | 支付回跳基地址，默认 `http://127.0.0.1:8000`；Vite 联调改 5173；上线填域名 |
| `COOKIE_SECURE` | HTTPS 部署设 `1` |
| `ALLOWED_ORIGINS` | 跨域白名单（逗号分隔），留空 = 仅同源（默认，推荐） |

## 6. 测试记录（2026-10-10 本地实测）

- 后端 curl 18 项：注册/重复注册 409/弱密码 400/登录 401/未登录下单 401/下单/mock 履约/会员生效/重复 confirm 幂等（vip 不变）/年卡叠加（+365 从 2026-11-09 → 2027-11-09）/vip quota/登出/webhook 无签名 400/重登录恢复会话 —— 全部通过
- 浏览器回归 8/8（`.workbuddy/verify-pay.js`）：注册 → mock 购买 → 成功页含有效期 → VIP 徽章 → English 参考价 ≈ $1.39 → 退出
- 门禁表达式实测：`bv*[height<=1080]+ba/b[height<=1080]/b` 在 B站测试视频（BV1heam6TExz）选流正确（1080），不破坏现有下载

**已知边界**
- B站未登录态最高 1080p（平台限制），清晰度门禁的实际差异需在 YouTube 4K 等场景验证；逻辑已由服务端强制，前端仅体验层
- 退款/争议不自动撤销会员（一次性购买时间制权益，后续可扩展）
- 批量下载、优先通道等 PLANS 文案中的权益仍未实现（与 04 号文档 P2 待办一致）
